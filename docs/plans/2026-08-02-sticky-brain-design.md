# Sticky Brain — always-on-top board for vault backlogs and live sessions

Status: built — phases 1 (read-only board) and 2 (ack/snooze/pin state) implemented; installer at `dist/`. Written 2026-08-02.

2026-08-03: phases 1–2 complete; the packaged installer had gone stale against `src/` and was rebuilt.

## Problem

Open work lives in four places that never meet on one screen:

- `Second Brain/wiki/Open Backlogs.md` — 82 KB, 18 `##` sections, one per project/session that opened them.
- `Second Brain/.inbox/*.md` — light-mode drafts. A record still in `.inbox/` root is the only copy of that work.
- `~/.claude/sessions/*.json` — the live agent sessions and what each is doing right now.
- `Second Brain/wiki/Project Change Evidence.md` — generated by `sb-watch.ps1`; branch and dirty counts per project.

Because none of it is visible, the agent has to re-raise open issues in conversation. The board
replaces that nagging with a surface the owner can glance at.

## Goal

One always-on-top desktop widget. Sticky cards, grouped. Read-mostly. Answers three questions
without opening Obsidian: *what is running*, *what is pending*, *what is owed*.

## Non-goals (cut deliberately)

- No task editing inside the widget. The vault stays authored by hand and by `/sb consolidate`.
- No cloud, no sync, no accounts. Local files only.
- No notification popups. The whole point is that the board is passive; you look at it.
- No mobile, no web deployment.

## Data sources — verified on disk 2026-08-02

### 1. Live sessions — `C:\Users\deped\.claude\sessions\<pid>.json`

Real shape, read from `18000.json`:

```json
{"pid":18000,"sessionId":"bf7e71a3-…","cwd":"C:\\Users\\deped","startedAt":1785676663801,
 "version":"2.1.220","kind":"interactive","entrypoint":"cli","name":"deped-fb",
 "nameSource":"derived","status":"busy","updatedAt":1785677107914,"statusUpdatedAt":1785677107914}
```

`status` is the live signal (`busy` / idle). `cwd` maps to the project via
`.automation/projects.json`. A stale file is one whose `pid` is no longer alive — check, don't
trust the file's existence. Two session files existed at design time.

### 2. Pending inbox — `Second Brain/.inbox/*.md` (excluding `done/`, `archive-*/`)

Fixed frontmatter (`type: sb-inbox`, `createdLocal`, `status: pending`) plus fixed `##` sections:
Task, Project, Notes used, Files touched, Decisions, Follow-ups, Unresolved questions.
**Follow-ups and Unresolved questions are the two fields the board surfaces** — they are owed work
that no wiki note holds yet. 1 record pending at design time.

### 3. Backlogs — `Second Brain/wiki/Open Backlogs.md`

Parse `##`/`###` headings as the group (project + what opened it), bullets as items. Read-only.

### 4. Repo state — `Second Brain/wiki/Project Change Evidence.md`

Generated. Branch, dirty count, suppressed count per registered project. Never parsed for file
contents; the watcher already screened those.

## Architecture — three options

**A. Obsidian-only (Bases view + Dataview).** Cheapest, zero new code. Fails the core ask: it is
not visible unless Obsidian is open and focused, and it cannot see `~/.claude/sessions/`.

**B. Electron widget — recommended.** A frameless, always-on-top, transparent-background window.
Main process owns all filesystem reads and a `chokidar` watcher; renderer draws sticky cards and
never touches `fs`. Ships today with npm only — no Rust toolchain, no PowerShell version ceiling.
Cost: ~150 MB resident. Acceptable for one persistent widget.

**C. Tauri v2.** Same window behavior at ~15 MB, but needs the Rust toolchain installed and a
Rust-side rewrite of every parser. Revisit only if B's memory turns out to matter.

Recommendation: **B**, with all parsing isolated behind one `sources/` module so a later port to C
is a rewrite of the shell, not of the logic.

## Component shape

```
sticky-brain/
  src/main/          Electron main — window, tray, always-on-top, watcher
    sources/
      sessions.ts    ~/.claude/sessions/*.json  + pid-liveness check
      inbox.ts       .inbox/*.md frontmatter + section parse
      backlogs.ts    wiki/Open Backlogs.md heading/bullet parse
      evidence.ts    wiki/Project Change Evidence.md table parse
    state.ts         board-state.json — acked / snoozed / pinned, app-local
  src/renderer/      React + Vite. Pure props in, no fs, no node integration.
  docs/plans/
```

## Data flow

1. Watcher fires on change in `.inbox/`, `wiki/Open Backlogs.md`, `wiki/Project Change Evidence.md`,
   `~/.claude/sessions/`. Debounce 300 ms.
2. Main re-reads only the changed source, merges into one `BoardSnapshot`, applies `state.json`
   (drops acked, hides snoozed until their timestamp), pushes to renderer over IPC.
3. Sessions additionally poll every 5 s — `status` flips `busy`/idle without a file rename on some
   paths, and a dead pid leaves the file behind.
4. Renderer renders. It never writes. Ack/snooze/pin go back over IPC to main, which owns
   `board-state.json`.

## Write policy — the load-bearing constraint

**The widget never writes into the vault.** Acknowledgement lives in the app's own
`board-state.json`, keyed by a stable item id (`source path + heading + normalized text hash`).
Marking a backlog item done in the widget would hand-edit a note that `/sb consolidate` also
edits — the exact split-ownership defect `Second Brain Project Automation Plan` records as the
recurring failure in this setup.

The one sanctioned write path, if wanted later: a "log this" button that shells out to
`.automation/sb-inbox.ps1`, which is the vault's own supported entry point. Phase 3, not phase 1.

## Error handling

- Vault path missing, or `.claude/sessions/` missing: render the card group as a visible
  "source unavailable — <path>" tile. Never an empty board that reads as "nothing pending".
- Parse failure on a note: show the group with a count of unparsed items. Silent truncation is
  the failure mode being designed against — the same reason `sb-watch.ps1` counts every
  suppression instead of hiding it.
- Dead pid with a live-looking session file: render as `stale` styling, not as running.
- `board-state.json` corrupt: back it up beside itself, start empty, tell the user on the board.

## Testing

- Parser unit tests against fixtures copied from the real files (a session json, one inbox
  record, a 3-section slice of `Open Backlogs.md`, one evidence table).
- One test per error path above — the "source unavailable" tile is the assertion that matters.
- Manual: kill a session process and confirm the card flips to stale within 5 s.

## Phases

1. **Read-only board.** Sessions + inbox follow-ups + backlogs. Always-on-top window, tray toggle.
2. **State.** Ack, snooze, pin, per-project collapse. `board-state.json`.
3. **Agent handshake (optional).** `sb-remind.ps1` reads `board-state.json` and stops re-raising
   acked items. This is the step that actually removes the nagging; phases 1–2 only make the
   nagging unnecessary.

## Open questions

- Does the ack state belong to the app or to the vault? App-local means it is lost on a reinstall
  and invisible to any agent that has not been taught to read it. Unresolved; phase 3 forces it.
- `Open Backlogs.md` bullets have no ids and no checkbox syntax. A text-hash id breaks when a
  bullet is reworded. No convention exists yet for stable item identity — recorded as a gap.
- Whether the board should show `wiki/log.md` at all. Excluded for now, matching the light-mode
  rule that routing a reader into the log is the cost the fast path exists to avoid.
